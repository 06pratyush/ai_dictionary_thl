# The Hallucinated Lab — Dictionary

Two corpora, one search, one page per term.

- **AI & Mathematics** — machine learning, statistics, optimisation, and the
  linear algebra underneath all of it.
- **Software Engineering Core** — algorithms, architecture, concurrency,
  databases, security, and the field's durable jargon.

A single search bar spans both. You can scope it to one section or search both
at once. Every term gets its own crawlable static page carrying definitions,
formal statement, etymology, sense-mapped synonyms and antonyms, cross-links,
and references.

Built to slot into [thehallucinatedlab.space](https://thehallucinatedlab.space)
as a new navbar section. 100% static, zero-build at runtime, no frameworks, no
trackers.

---

## Quick start

```bash
python build/build.py
```

That validates both corpora, then writes `index.html`, `terms/*.html`,
`data/search-index.json` and `sitemap.xml`. Serve the directory with anything:

```bash
python -m http.server 8000
```

The search index is fetched over HTTP, so open `http://localhost:8000` rather
than the file directly — `file://` will block the request.

```

  software-engineering.json  corpus two — the source of truth
  search-index.json          GENERATED — do not edit
build/
  validate.py                schema + lexicographical gate
  build.py                   static generator; owns everything generated
  merge_generated.py         normalises and gates locally-generated entries

assets/
  css/tokens.css             design tokens, mirrors DESIGN-LANGUAGE.txt
  css/dictionary.css         search bar, corpus grids, term page
  js/search-engine.js        the Series 700 engine
  js/app.js                  hub controller (progressive enhancement)
  js/nav.js                  shared navbar behaviour
terms/                       GENERATED — one page per entry
tests/
  search-engine.test.mjs     26 conformance cases, no framework
docs/ENTRY-SCHEMA.md         the entry contract
CONTEXT.md                   architecture, gaps, append-only timeline
```

`terms/`, `index.html`, `data/search-index.json` and `sitemap.xml` are build
artefacts. Never hand-edit them — the next build overwrites your changes, and
CI fails the commit if they are stale.

## Adding a term

1. Append an entry to the relevant file in `data/`, following
   [docs/ENTRY-SCHEMA.md](docs/ENTRY-SCHEMA.md). Take the next free LID.
2. Run `python build/validate.py` until it is clean.
3. Run `python build/build.py`.
4. Append a log entry to Section 5 of `CONTEXT.md` — CI enforces this on
   every pull request.

The validator is strict on purpose. It will reject:

- a duplicate LID or slug,
- a definition that restates its own headword (Rule 502),
- a definition missing an example sentence (Rule 507),
- a synonym or antonym not mapped to a specific sense (Rule 521),
- an entry with no citation,
- an `ngram` class disagreeing with the headword's word count.

## The search engine

`assets/js/search-engine.js` implements Series 700 of the lexicographical
framework and has no dependencies. It runs entirely in the browser.

**Query handling.** Input is lowercased, stripped of diacritics, and flattened
of punctuation, so `Bayes' Theorem`, `bayes theorem` and `BAYES-THEOREM` are the
same query. Stop words stay literal in short queries and are dropped from long
ones.

**Typo tolerance.** Damerau-Levenshtein distance with an edit budget that scales
with word length (1 edit under 5 characters, 2 up to 9, 3 beyond). Substitutions
are weighted by QWERTY adjacency, so `s`-for-`a` scores as a likelier slip than
`m`-for-`a`. Adjacent transpositions are corrected directly. If nothing matches
at all, a Metaphone pass routes `flegm` to `phlegm`.

**Ranking.** An exact headword scores 10×, an inflected form or abbreviation 8×,
an anchor word inside a multi-word term 5×, and a mention buried in a definition
1×. Corpus frequency breaks ties without overturning tiers, and terms flagged
archaic take a 50% penalty so they cannot outrank a live equivalent on a fuzzy
hit.

**Modifiers.**

| Syntax | Effect |
| :--- | :--- |
| `"kick the bucket"` | exact phrase; fuzzy matching and phonetics are bypassed |
| `*ology` | wildcard — `*` is any run of characters, `?` is exactly one |
| `gradient AND descent` | both terms must be present |
| `tensor NOT physics` | excludes entries mentioning the second term |

Run the conformance suite with `npm test` — 26 cases, one per rule.

## Delegation pipeline

Bulk corpus work is generated by a local model under Ollama and gated before it
reaches `data/`. See [.orchestrator/session.md](.orchestrator/session.md) for
the run ledger.

```bash
bash .orchestrator/warm.sh
python .orchestrator/corpus_batch.py .orchestrator/termlist-aim.json .orchestrator/tmp/gen-aim
python build/merge_generated.py .orchestrator/tmp/gen-aim data/ai-mathematics.json   # dry run
python build/merge_generated.py .orchestrator/tmp/gen-aim data/ai-mathematics.json --apply
```

The batch script is resumable — it skips any term already on disk.

**What the pipeline is trusted with.** Definitions, example sentences and
citations came back accurate and usable. **What it is not:** word origins. The
model produced contentless filler in most entries and, where it produced a real
derivation, it was wrong. Any etymology matching those shapes is replaced with
`[Origin obscure]` per Rule 517 and listed for a human to write. Nothing
generated reaches `data/` without passing `validate.py`.

## Accessibility

Every page carries a skip link, semantic landmarks, exactly one `<h1>`, and a
2px gold focus ring via `:focus-visible`. The suggestion dropdown is a proper
combobox — arrow keys move through it, Enter opens, Escape closes.

This project ships `--text-muted` at `#827b74` (4.60:1 on `--bg-card`, WCAG AA
pass) rather than the parent site's `#5a5550`, which measures 2.60:1 and fails.
The divergence is deliberate and logged as GAP-01 in `CONTEXT.md`.

With JavaScript disabled the hub still lists both corpora in full and every term
page renders completely. Only search is lost.

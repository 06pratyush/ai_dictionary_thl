# THE CONTEXT SYNCHRONIZATION ENGINE: MASTER PROTOCOL

## 1. The Continuous Synchronization Mandate (Zero-Tolerance Policy)

The `CONTEXT.md` file is the immutable brain and persistent memory of the project. To prevent "vibe drift" and context amnesia, the following rule is absolute:

**The `CONTEXT.md` file MUST be updated at EVERY instance of change.**

* **Every AI Action:** If an AI agent modifies even a single line of code, its final output *must* include an appended log entry to `CONTEXT.md`.
* **Every Human Commit:** No code can be committed locally without a corresponding timeline update.
* **Every Pull Request & Merge:** No branch can be merged into `main` or `develop` unless the PR explicitly includes a modification to the `CONTEXT.md` timeline documenting the scope of the merge.

## 4. Automated Enforcement (Pull Request & Merge Gatekeeper)

To guarantee that no change slips through during merges or PRs, you must enforce the rule at the CI/CD level.

Create this GitHub Actions workflow at `.github/workflows/enforce_context_update.yml`. This script will automatically **fail and block any Pull Request** that does not include an update to `CONTEXT.md`.

```yaml
name: Enforce CONTEXT.md Synchronization

on:
  pull_request:
    branches: [ main, develop ]
    types: [opened, synchronize, reopened]

jobs:
  audit-context-file:
    runs-name: Check for CONTEXT.md updates
    runs-on: ubuntu-latest
    
    steps:
      - name: Checkout Code
        uses: actions/checkout@v3
        with:
          fetch-depth: 0
          
      - name: Verify CONTEXT.md modification
        run: |
          echo "Auditing Pull Request for Context Synchronization..."
          
          # Get the list of modified files in this PR
          MODIFIED_FILES=$(git diff --name-only origin/${{ github.base_ref }}...${{ github.sha }})
          
          # Check if CONTEXT.md is in the list of modified files
          if echo "$MODIFIED_FILES" | grep -q "^CONTEXT.md$"; then
            echo "SUCCESS: CONTEXT.md has been updated in this Pull Request."
            exit 0
          else
            echo "::error::PROTOCOL VIOLATION: CONTEXT.md was not updated!"
            echo "Every Pull Request and Merge MUST include an appended log entry in CONTEXT.md."
            echo "Please update Section 5 of CONTEXT.md with the details of this merge and push again."
            exit 1
          fi

```

### Why this specific setup works:

1. **Psychological Check:** The AI is instructed in its system prompt that its job is not done until the file is updated.
2. **Local Check:** The Git pre-commit hook (from the previous protocol) stops local human errors.
3. **Remote Check:** The CI/CD YAML above acts as the final gatekeeper—if an AI or human tries to force a merge into your main branch without logging the architectural changes in `CONTEXT.md`, the repository will reject the merge entirely.
